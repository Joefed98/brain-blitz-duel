## 2. Fairness and replay constraints

- **Rated pairing ignores the device.** `src/lib/rated/matchmaking.ts:166-178` `canPair`: same format, same choice, both placement or both placed, rating band. No `input_type`, layout or device anywhere under `src/lib/rated/` (grep: none). `src/lib/inputType.ts:1-11`: `input_type` ("touch" / "mouse" / "keyboard" / mixes) is stored on `round_results`, `async_results`, `practice_plays` for later leaderboard splits; "never reaches grading or scoring and nothing reads it in the app".
- **Recorded rated runs are matched by game version**: `matchmaking.ts:257-267` `gameVersionOf(puzzle)` = `stampSignature` minus `tieRev`, plus `level=` off Normal; `:270-290` `recordedRefusal`: `old_version` when `g.signature !== dealtSignature(type)`, `level` off Normal, `other_format`, `retired`, `flagged`. So **any new stamp retires every recorded run of that game from the rated pool** until new ones accumulate (14-day window, `RECORDED_WINDOW_MS`). `src/lib/data/ratings.ts:47` `RATED_VERSIONS = ["classic"]`; `src/lib/rated/match.ts:108` refuses other versions.
- **desktop-fairness-check** (`scripts/desktop-fairness-check.ts:1-24`) asserts: (1) the rotor mapping round-trips (`rotatePoint`/`unrotatePoint`, 2,000 boxes), keys and swipes on a turned world; (1b) no rotated text on Cue Ball; (2) **static separation: no sim, replay or grader under `src/lib/arcade/**` (renderers excluded) or the duel graders/replays imports the layout, presentation, tap mapping, window size or matchMedia**; (3) real gestures on Cue Ball (rotate), Apex (tall), Free Cell (wide) at 1440×900 and 1920×1080 with a mouse and on two phone sizes reach the stage as the same world points and identical payloads; (4) those payloads fed to the sim give the same state, score and checksum. **Any option where the desktop world differs (B, and A/D during a transition) fails (3) and (4) by design and would need the check rewritten, which breaks the rule that assertions are never loosened.**
- **arena-world-check** (`scripts/arena-world-check.ts:1-17`): every active arcade play screen has the same `--arena-w/--arena-h` on phone 390×844, sideways tablet 1180×820 and computer 1440×900, the drawn box has the world's aspect within a pixel, the whole world is on screen, and the tablet/computer draw it at least as large as the phone (Apex excepted). A desktop-only world fails this outright.
- **arcade-play-check --desktop** (`scripts/arcade-play-check.ts:97-107`): 1440×900 and 1920×1080, 6 s of scripted input, 60 fps as mean rAF gap ≤ `DESKTOP_FRAME_MS` = 16.7 × 1.1 = 18.3 ms. Bigger canvases cost frames (why Apex is capped at 340 and the rotor at 1,000 px: `desktop-layout.css:449-451`).
- **Server replay**: every arcade result is the server's replay of the input log (`src/lib/duel/arcade.server.ts`, 681 lines, deals; the per-game `replay<Game>Run(seed, raw, rev[, level])` functions live in `src/lib/duel/<game>.ts` / `src/lib/arcade/*` (list: replayBreakerRun, replayRallyRun, replayWavefrontRun, replayBurstRun, replayBeatRun, replaySnakeRun, replayCrossRun, replayBlockfallRun, replayMinigolfRun, replayPoolRun, replayCurlingRun, replayHomerunRun, replayFreekickRun, replayRacingRun, replaySportsRun, replayFlipRun, replaySwingRun, replayNinjaRun/replayMoonRun, replayBastionTankRun, replayOrbitRun, replayTiltRun, replayMatchupRun, replayBubbleRun, replayInkBridgeRun, replayBallTrackRun, replayMahjongRun, replayTripeaksRun, replayFiveHandsRun, replayPyramidRun, replayArcadeRun…). Inputs in logs are world units (pointer kinds carry x/y in world px or 1/256 px; e.g. Tilt `inputRange(TILT_INPUT_DRAG, [0, TILT_WORLD_W], …)` `tilt.ts:49`, Home Run `HOMERUN_INPUT_RANGES_V4` `homerun.ts:643`). A wider world changes the input range → a new stamp, with the old stamp's world kept for replay (the `brkWorldW(state)` pattern).
- **Proved banks/deals** (table above): Wavefront, Blockzone (seed-only), Crazy Golf, Cue Ball, Curl Champ, Home Run, Top Bins, Apex, Free Cell, Summit, Roofbound, Grappler, Orbit, Tilt, Rainbow Bridge, Ball Tracker, plus the per-level banks. Each witness is an input log or line in world coordinates proved at 200 through the server replay; a world change invalidates every witness of a physics game (`scripts/<game>-deal.ts` / `-bank.ts` rebuild; `scripts/arcade-standard/<type>.ts` 200 proof; `arcade-standard-check`). Blockzone's and the cards' deals are world-independent.
- **Intro demos**: recorded input logs with world positions (`src/lib/arcade/introDemo.ts:43-60` `demoTouches(raw, worldW, worldH)` reads x/y in world units); each game's demo plays only on listed stamps (`src/lib/duel/introDemo.functions.ts:58-130` `SAME_PLAY_DEMO_REVS`, `ACTION_DEMO_REVS`, `NUMBER_DEMO_MIN_STAMPS`, per-family rules `:181-414`). Fixtures `scripts/fixtures/{action,retro,strategy,sports,cards,home-run-top-bins,crazy-golf}-demos.json` + `scripts/<family>-demos-record.ts` / `-check.ts` / `-save.ts` (the manual "Save intro demos" workflow). A new stamp stops the demo until re-recorded.
- **The Daily**: `src/lib/duel/daily.server.ts:51-58` `dailyRoundOrder` → `pickRoundOrder` over `["arcade"]` for Daily Arcade, then `dealRounds(..., level: modeLevel("daily", null))` (`:75-81`, always Normal). The stored daily keeps its puzzles, so an older stamp replays in its own world; nothing to migrate, but a desktop-only world could never be a Daily (one board for everyone).
- **Rooms** (rule 5): every player gets the same stored puzzle/stamp; phone and desktop players sit in the same room, so a world can only differ by stamp, never by device.
- **Checks that pin the world or pixels** and would need re-recording under A/D: `arcade-play-check` baseline (`scripts/fixtures/arcade-play-baseline.json`, `.github/ci/arcade-play-baseline.json`), `room-practice-parity-check` (`ARCADE_WORLDS`), `bottom-clearance-check`, `arcade-device-bottom-check`, `arcade-fill-check`, `arcade-room-practice-check`, `arena-world-check`, `desktop-layout-check`, `retro-overhaul-check` (text floor by world), `skins-default-check` (frame digests for Cue Ball, Crazy Golf, Curl Champ, Apex, Top Bins, Full House, Free Cell + the four redesigned card games: `scripts/skins-default-check.ts:1-25`; a redraw goes in `skins-default-frames-overhaul.json` with approval), `racing-render-check`, each game's legacy replay check, `deal-identity-check` fixture, `practice-stamps.ts` → `PRACTICE_STAMPS` (a new stamp = a fresh practice best and new `dealtSignature`), `arcade-help-bands-check` / `intro-score-text-check` (help text), `tile-scenes-check` (re-export tiles if the look changes), `reveal-palette-check`.
- **Tile scenes** (`scripts/shots/tile-scenes/scene.tsx:1-18`, 104 px hand-made states) and `public/intro/<type>.webp` stills (`strategy-stills.ts`) are drawn from renderer painters: unaffected by a layout option, re-exported only if art changes.

## 3. Options A–D: cost and fairness

Common baseline: today the sim never reads the presentation (fairness check section 2), so **anything that only changes what surrounds the world is free of stamps, banks, replays and rated rules**.

### A. A wider world for everyone under a new revision stamp
Per game that reads its world size in the sim (every physics game in the table): a new `<game>Rev`, the new width carried in the state (pattern: `breaker.ts:1286-1287` `worldW/worldH` in init, read by `brkWorldW(state)`; folded into the checksum as Breaker does at `:753`), the stage's `worldW={…For(rev)}` function extended (every `src/puzzles/<game>.tsx` already dispatches on the stamp), `ARCADE_FX_SPECS`/`fxSpecAt`, `ARENA_FILL_*` painters, `LIVE_BANDS`, `scripts/scoring-targets-revs.ts` maps (`LIFT_REVS`/`STD_REVS`/`RETRO_REVS`/`AUDIT_REVS`), `scripts/arcade-standard/<type>.ts` entry and the 200 proof, bots in `scripts/arcade-skill-bands/bots/<game>.ts` (bands re-measured: a wider court changes every median), the game's `docs/arcade-standard/<game>.md` page, `bun scripts/practice-stamps.ts`, `deal-identity-check` fixture, the self-replay entry appended, a legacy fixture recorded on main, the intro demo re-recorded, `retroTextFloorFor` (wider → text drawn bigger in world px for the phone), and for banked games the bank/deal re-proved (`wavefront-big-deal.ts`, `orbit-fuel-bank.ts`, `swing-slide-deal.ts`, `tilt-deal.ts`, `ink-big-deal.ts`, `flip-deal.ts`, `balltrack` deals, `homerun-innings-deal.ts`, `freekick-layered-deal.ts`, `racing-deal.ts`, `pool-bank.ts`, `minigolf-bank`, `curling-bank.ts`). Recorded rated runs of that game drop out (`old_version`) for up to 14 days; practice bests restart.
**Fairness**: fair in rated play and rooms (one world for all), but the **phone pays**: a 390 px phone draws a W-wide world at 390/W (Breaker/Rally already 0.929, Meteor 0.833; a 560-wide court would be 0.70), so targets, text and gaps shrink on the device most players use, against the 11 px Retro text rule and the 44 px target rule. For paddle games width also changes the game's feel (longer ball travel across, more ground for the paddle to cover) rather than giving "more room" neutrally. This is a gameplay retune, not a layout fix.

### B. Desktop-only worlds, kept out of rated and Daily play
Would need a "wide" variant stamped on the deal like a level (`level` field pattern, `src/lib/levels/`; `gameVersionOf` already treats a level as another version, `recordedRefusal` → `level`), dealt only in practice for a desktop deal request (the server cannot trust a "desktop" claim: the client would ask for the variant; a phone could too), plus every sim/stage/replay/fx/bank item of A for the variant's world. **Rooms are dealt once for everyone** (rule 5, `startDealtRoom`), so a desktop player in any room, the Daily, challenges and rated play still gets the phone column: B improves practice only. It also fails `arena-world-check` and `desktop-fairness-check` sections 3–4 unless rewritten, which the house rules forbid. Separate stars/bests per variant (`PRACTICE_STAMPS` signature) or stars never earned on it. Low value for high cost.

### C. The same world with side panels filling the space (presentation only)
No stamp, bank, replay, demo or rated change; `arena-world-check`, `desktop-fairness-check`, `room-practice-parity-check` stay green by construction. Cost is design and front-end only: (i) decide what fills the two side regions at 1440×900 (~560 px in total today under the fade): the existing 320 px `ArenaGamePanel` (timer, score, stars, status, goal, challenges, controls) could become a two-sided or richer layout (left: live stats read from the sim through a display-only observer like `src/lib/duel/liveScore.ts` / the sound observers in `gameSounds.ts`, the run timeline the reveal already computes in `src/lib/replay/retroSummary.ts`; right: standings in a room, the chat, next game); (ii) optionally move canvas HUDs out of the world on the arena (a renderer flag `hud: false` per game: `retroHud` in `retro.renderer.ts`, `drawActionHud`, `drawHudPillRow`, the cards' `drawChip`), which touches frame-digest checks (`skins-default-check` for the skinnable/card games, `retro-overhaul-check` renders in Node, `racing-render-check`) and the bounds/text-floor rules; (iii) widen the `tall` column cap (`desktop-layout.css:453` 640 px) only if a world's aspect ever binds (it does not at 900 px tall); (iv) `arcade-play-desktop-check` at 60 fps with any new side canvases (the ambient layer already throttles by area, `ArcadeArenaSlot.tsx:181-182`); `desktop-layout-check`, `theme-check`/`no-wrap-check` screens for the new panels. **Fairness**: none at stake; a desktop player sees the identical world, as now.

### D. Per game: wider world for some, column + panels for the rest
A's per-game cost for the chosen games (Breaker, Rally, Wavefront, Fission, Pinball, Meteor each read width in the sim; Blockzone does not) plus C for everyone. Each chosen game is a new stamp with a re-measured curve and (Wavefront) a re-proved deal; Pinball's table is hand-laid geometry (`pinball4.ts`), so "wider" means a new table, not a parameter. The phone-scale penalty of A applies to exactly the games chosen. Blockzone is the one game on the list where a desktop-shaped layout (well centred, Next/Hold/stats to the sides, the glow carried out) is purely renderer work: `bfLayout(rev)` (`blockfall.renderer.ts:72`) could take the presentation (display only; a bigger `--arena-w` on desktop would still trip `arena-world-check`'s same-size rule unless the extra width is drawn as scene, not world).

|---|---|---|

| Breaker, Rally | **wider world would genuinely help the look** (a 420×784 court is tall and narrow on a landscape screen) but it is a new stamp with a refitted curve and bands; the state already carries `worldW/worldH`, so the plumbing exists; phones would draw at 390/W |

Net: **C now for everyone; D only if Joe wants Breaker/Rally (and perhaps Blockzone as a free cabinet layout) redesigned as games, each under its own stamp with the full A cost.** B is not worth building.
